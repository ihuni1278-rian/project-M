# 애니토이 프로젝트 허브 v0.1

PC에서 확인할 수 있는 기능 검증 구현본입니다. 운영 서비스가 아닙니다.

## 실행
Node.js가 있으면 `npm test`로 처리 규칙을 검증합니다.
Python이 있으면 이 폴더에서 `python -m http.server 8080` 실행 후 http://localhost:8080 접속합니다.
또는 정적 웹 서버로 이 폴더를 제공합니다. ES 모듈을 사용하므로 index.html을 더블클릭하는 file:// 실행은 지원하지 않습니다.

시험 아이디: 관리자 또는 연구원 / 초기 비밀번호: 1111
첫 로그인에서 8자 이상 비밀번호로 변경합니다.
이 시험본은 계정 정보와 자료를 브라우저 localStorage에 저장합니다. 실제 비밀번호·개인정보·사업자료를 사용하지 마세요. 브라우저 데이터 삭제 시 자료가 삭제됩니다.

## 구현된 기능
- 월간 업무 입력, 담당자 배정, 기간 및 완료기준 지정
- 실적·이슈·상태 입력, 원래 기한을 유지한 업무 이월
- 회의록 입력 및 확정 시 후속 업무 생성, 중복 방지
- 업무 기한과 회의 일자를 월간 달력에 표시
- 산출물 등록, 파일 버전 추가, 버전별 승인·반려·제출, 파일 다운로드
- 사업비 예산 및 집행 예정·완료·취소 내역, 음수 환불 입력
- 연구원별 업무 집계
- 기간별 근거 업무 ID가 포함된 보고서 초안, 수정, TXT 다운로드
- 시험 계정 생성·역할·사업비 권한·중지, 변경 이력, JSON 백업
- 반응형 화면 및 Netlify 정적 배포 설정

## 아직 완료되지 않은 운영 요구사항
- Supabase Auth 연결, 이름 로그인용 서버 처리, 개인별 임시 비밀번호 발급
- 서버에서 강제하는 최초 비밀번호 변경과 관리자 권한 검증
- 프로젝트별 멤버십 UI 및 전체 업무 데이터의 Supabase 저장
- 회의·산출물·예산·보고서 운영 테이블, 파일 Storage 정책
- 주별 계획 전주 자동 호출, 보고서에 회의·산출물·사업비 통합
- 회의 다중 결정사항 및 확정 후 수정 동기화, 사용자 알림
- 산출물 제출 증빙, 업무 실적 증빙, 공식 마일스톤 승인 판정
- 보고서 승인/확정, 예산 증빙 업로드와 변경 이력 상세화
- 실제 브라우저 시나리오 검증 및 운영 RLS 권한 침투 테스트

supabase/001_schema.sql은 일부 운영 테이블 및 접근 정책의 시작점이며 아직 실제 DB에 적용하지 않았습니다. 완성된 운영 백엔드로 간주하지 마세요.

## GitHub → Netlify → Supabase 연결
1. 이 폴더의 소스를 선택한 GitHub 저장소에 올립니다.
2. Netlify에서 해당 저장소를 선택합니다. 빌드 명령 없이 publish 디렉터리는 `.`입니다.
3. Supabase 프로젝트를 연결한 뒤 운영 인증·데이터 어댑터와 나머지 마이그레이션을 완성합니다.
4. 시험 저장 모드를 제거하고 권한·동시 수정·파일 접근·복구를 검증한 후 실제 사용자를 등록합니다.

현재 GitHub 저장소 등록/푸시, Netlify 배포, Supabase 연결은 수행되지 않았습니다.
